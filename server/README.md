# all-cash-server

Серверная часть приложения учёта личных финансов `all-cash`. Хранит копию данных
каждого пользователя, синхронизирует их с устройством в обе стороны и отдаёт
CSV-выгрузку.

Устройство системы целиком описано в `ARCHITECTURE.md`, причины принятых решений —
в `docs/adr/`.

## Доступ к серверу

**Сервер работает только в локальной сети.** Порт наружу не публикуется,
проброс портов на роутере не настраивается.

Это осознанный выбор из списка раздела 5.2 технического задания. Вход в
приложение идёт по одному логину, без пароля: логин разделяет данные
пользователей, но не защищает их. Любой, кто знает чужой логин и находится в той
же сети, читает и меняет чужие операции.

Прежде чем сервер станет доступен за пределами локальной сети, нужно закрыть его
одним из способов: VPN (WireGuard или Tailscale), список разрешённых IP-адресов
на прокси либо HTTP Basic Auth на прокси с общим секретом. До этого порт
наружу не открывать.

HTTPS обязателен при любом доступе извне. Внутри локальной сети допустим HTTP.

## Стек

Go 1.26+, SQLite одним файлом, роутер `chi`, драйвер `modernc.org/sqlite` без
cgo, денежные суммы — `shopspring/decimal`. Сторонних зависимостей больше нет.

## Запуск

```sh
cp .env.example .env   # значения по умолчанию рабочие
make run               # запустить сервер
```

`make run` подключает `.env` целиком. Сервер читает тот же файл и сам, поэтому
`go run ./cmd/server` работает без `make`.

Сборка бинарников:

```sh
CGO_ENABLED=0 go build -o bin/server ./cmd/server
```

### Docker Compose

```sh
docker compose up -d          # таблицы создаёт server при старте
docker compose logs -f server
docker compose down           # каталог data с базой остаётся
```

Порт по умолчанию привязан к `127.0.0.1`: сервер доступен только с самой машины.
Чтобы его увидели устройства локальной сети, укажите адрес машины:

```sh
ALL_CASH_BIND_ADDRESS=192.168.1.10 docker compose up -d
```

Наружу порт не открывать. `ALL_CASH_SERVER_PORT` задаёт порт и на хосте, и внутри
контейнера.

Настройки Compose берёт из `.env` рядом с `docker-compose.yml` и целиком передаёт
их в контейнеры (`env_file`): отдельного списка переменных в `docker-compose.yml`
нет. Без `.env` запуск не состоится.

База лежит в каталоге на хосте — `ALL_CASH_DATA_DIR` (по умолчанию `./data`), внутри
контейнера он смонтирован как `./data` относительно рабочего каталога. Файл
доступен обычными средствами: `sqlite3 ./data/all_cash.db`. `docker compose down`
данные не трогает; удалить их можно только вручную.

На Linux каталог принадлежит хостовому пользователю, а процесс в контейнере
работает под uid 10001 — запись не удастся, `server` упадёт с `unable to open
database file`. Укажите в `.env` свои идентификаторы:

```sh
ALL_CASH_DOCKER_USER=$(id -u):$(id -g)
```

Не запускайте `make run` и Compose одновременно: это два процесса поверх одного
файла SQLite.

После изменения кода: `docker compose up -d --build`.

### Docker без Compose

```sh
docker build -t all-cash-server .
docker run -d --env-file .env -p 192.168.1.10:8000:8000 -v "$PWD/data:/app/data" all-cash-server
```

Публикация порта в виде `-p 8000:8000` привязывает его ко всем интерфейсам хоста —
указывайте адрес явно.

## Схема базы

При старте `server` выполняет `migrations/schema.sql` целиком. Скрипт написан через
`IF NOT EXISTS`, поэтому перезапуск безвреден и данные не теряет. Существующие таблицы
не изменяются: новый столбец в уже созданной базе нужно добавить вручную. SQL вшит в
бинарник, каталог `migrations/` при развёртывании не нужен.

## Заведение пользователей

Ручкой `POST /auth/register`:

```sh
curl -XPOST http://localhost:8000/auth/register -d '{"login":"oleg"}'
# {"userId":"efa1a6e4-…","login":"oleg"}
```

Логин приводится к нижнему регистру и обрезается по краям — теми же правилами,
что и на клиенте. Занятый логин даёт `409` с кодом `login_taken`, логин короче
трёх символов — `400`.

> **Ручка `/auth/register` ничем не закрыта.** Техническое задание её запрещает
> именно поэтому: вместе с входом без пароля она означает, что любой, кто
> достаёт до сервера, заводит себе логин и работает с сервером. Это терпимо,
> пока сервер живёт в локальной сети. Перед выносом сервера наружу ручку нужно
> либо убрать, либо закрыть секретом администратора.

## Ручки

| Метод | Путь | Заголовок сессии | Назначение |
| --- | --- | --- | --- |
| `GET` | `/health` | не нужен | проверка доступности |
| `POST` | `/auth/login` | не нужен | опознание по логину |
| `POST` | `/auth/register` | не нужен | заведение учётной записи |
| `GET` | `/pull?since=N` | нужен | изменения после курсора `N` |
| `POST` | `/push` | нужен | приём записей с устройства |
| `GET` | `/export/csv` | нужен | выгрузка живых операций |

Тело запроса ограничено 10 МиБ. Запрос больше этого размера получает `413` с кодом
`payload_too_large`.

Заголовок сессии — `X-Login: <логин>`. Отсутствующий или неизвестный логин даёт
`401` с кодом `invalid_token`; неизвестный логин на `/auth/login` — `401` с кодом
`unknown_login`. Коды различаются: по первому клиент сбрасывает сессию, по
второму показывает ошибку на экране входа.

Курсор двигает только `/pull`. `/push` его не трогает никогда.

## Переменные окружения

Настройки разделены на две группы: `APP_` — приложение, `SERVER_` — HTTP-сервер.

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `ALL_CASH_APP_DB_PATH` | путь к файлу SQLite (относительный — от рабочего каталога) | обязательна |
| `ALL_CASH_APP_PULL_LIMIT` | записей в одном ответе `/pull` | `2000` |
| `ALL_CASH_APP_LOG_LEVEL` | уровень логирования | `info` |
| `ALL_CASH_SERVER_PORT` | порт HTTP | `8000` |
| `ALL_CASH_SERVER_READ_TIMEOUT` | таймаут чтения запроса | `30s` |
| `ALL_CASH_SERVER_WRITE_TIMEOUT` | таймаут записи ответа | `30s` |
| `ALL_CASH_SERVER_SHUTDOWN_TIMEOUT` | ожидание graceful shutdown | `10s` |

Ещё три переменные читает только `docker compose`, приложение их не знает:

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `ALL_CASH_DATA_DIR` | каталог хоста с базой, монтируется в `/app/data` | `./data` |
| `ALL_CASH_DOCKER_USER` | пользователь процесса в контейнере | `10001:10001` |
| `ALL_CASH_BIND_ADDRESS` | адрес, на котором публикуется порт | `127.0.0.1` |

Настройки читает `internal/config` через `cleanenv`. Файл `.env` из рабочего
каталога подхватывается автоматически — импортом `godotenv/autoload`.
**Заданная переменная окружения перекрывает файл** — в контейнере настройки
приходят переменными, и файл не должен их затирать. Отсутствие файла ошибкой не
считается, отсутствие `ALL_CASH_APP_DB_PATH` валит запуск.

## Резервное копирование

Ежедневно по cron:

```sh
sqlite3 $ALL_CASH_APP_DB_PATH ".backup /backup/all_cash-$(date +%F).db"
```

Хранить 30 последних копий. Простое копирование файла без `.backup` запрещено:
в режиме WAL оно даёт повреждённую копию.

## Тесты

```sh
go test ./...
go test -race ./...
```

Тестами покрыт только слой бизнес-логики `internal/usecase`; слой данных там
мокается. Тестов репозитория, настроек и транспорта нет — изменения в SQL
проверяются вручную через `api.http`.

## Логи

Структурные JSON-логи в stdout через `log/slog`, по строке на запрос: метод,
путь, код ответа, длительность, `user_id`, а для `/pull` и `/push` — параметры
курсора и число принятых записей. Логины, токены и тела запросов не логируются.
