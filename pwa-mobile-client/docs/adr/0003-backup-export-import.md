# ADR-0003: Резервная копия, импорт и клиентский экспорт CSV

- Статус: Принято
- Дата: 2026-09-30
- Заменяет: — (уточняет работу `features/export`, введённую без отдельного ADR)
- Связанные ADR: [0001](0001-web-client-architecture.md), [0002](0002-interface-localization.md)

## Контекст

Экспорт CSV раньше делал сервер (`GET export/csv`). Он требовал сети и входа, не работал офлайн и не позволял восстановить данные: CSV не содержит идентификаторов, скрытых счетов, типов категорий и связей долгов с погашениями. Нужен способ делать резервную копию всех данных и восстанавливать её на любом устройстве, в том числе без сети. Источник данных на клиенте — IndexedDB (ADR-0001, п. 2).

## Варианты

1. **CSV как формат копии** — один формат для людей и для восстановления. Плюсы: одна кнопка. Минусы: теряет структуру, разбор хрупкий, деньги и связи ломаются.
2. **Серверная копия** — сервер отдаёт и принимает дамп. Плюсы: нет логики на клиенте. Минусы: нужен сервер и новый протокол, нет офлайн.
3. **Клиентская копия в JSON + клиентский CSV** — оба файла строятся из данных `ledgerStore` в браузере. Плюсы: работает офлайн, без изменений сервера, полная структура. Минусы: логика формата и проверки на клиенте.

## Решение

Выбран вариант 3.

- **Копия.** JSON-файл `allcash-backup-YYYY-MM-DD.json`: `{ format: "allcash-backup", version: 1, exportedAt, accounts, categories, operations }`. Записи — модель `core/model/ledger.ts` как есть, включая мягко удалённые (`deletedAt`), чтобы удаления тоже доехали до сервера.
- **Версия.** `version` растёт при несовместимом изменении формата. Файл с более новой версией отклоняется. Файл со старой версией читается.
- **Импорт — слияние по `id`.** Запись из копии заменяет локальную с тем же `id`, остальные локальные записи сохраняются. Локальные данные не очищаются.
- **Синхронизация.** Импортированные записи получают `syncState: pending` и `seq: null`, независимо от значений в файле. Следующая синхронизация отправляет их на сервер (ADR-0001, п. 6). Курсор `sync.lastSeq` импорт не меняет.
- **Проверка.** `parseBackup` в `core/model/backup.ts` проверяет структуру, типы, `kind` операций, цвета палитры и даты до записи. Ошибка — `BackupFailure` с путём к полю. При ошибке в IndexedDB ничего не пишется. Запись идёт одной транзакцией (`LedgerRepository.importSnapshot`).
- **CSV.** Только для чтения человеком и таблицами, импорта нет. Строится на клиенте из живых операций: `operationsCSV` в `core/model/backup.ts`. UTF-8 с BOM, разделитель `;` для ru и `,` для en, `\r\n`. Суммы — с точкой и двумя знаками, расходы отрицательные. Ячейки, начинающиеся с `=`, `+`, `@`, табуляции, экранируются апострофом (защита от формул). Заголовки и типы локализованы (ADR-0002).
- **Слои.** Формат, разбор, проверка и CSV — в `core/model` без Vue. Запись — через `LedgerRepository`. `ledgerStore` даёт `snapshot()` и `importSnapshot()`. `features/export` содержит только UI и вызов скачивания.
- **Сервер.** Эндпоинт `export/csv` клиент больше не вызывает. Экспорт не требует входа и сети.

## Последствия

- Проще: резервное копирование и перенос между устройствами без сервера. Экспорт работает офлайн.
- Сложнее: формат копии — публичный контракт. Менять его можно только с повышением `version` и поддержкой чтения старых версий.
- Импорт слиянием не удаляет записи, которых нет в копии. Полная замена данных делается через «Очистить локальные данные», затем импорт.
- Записи одного `id` из копии перезаписывают более новые локальные правки. Пользователь предупреждён текстом `export.info`.
- Проверка соблюдения: `npm run typecheck`. Вручную — сохранить копию, очистить данные, импортировать, сверить счета и балансы; открыть CSV в Excel.
