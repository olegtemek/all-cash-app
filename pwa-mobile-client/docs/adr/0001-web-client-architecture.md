# ADR-0001: Архитектура веб-клиента AllCash

- Статус: Принято (пункт 8 частично заменён ADR-0002, пункт 6 частично заменён ADR-0004)
- Дата: 2026-09-30

## Контекст

AllCash — приложение для личных финансов: операции, счета, долги, категории, аналитика. Веб-клиент является PWA и должен работать без сети. Данные синхронизируются с сервером, когда он доступен. Клиент повторяет доменную модель и поведение нативного iOS-приложения, поэтому часть именования взята из Swift (`UUID`, `LedgerRepository`, названия SF Symbols).

Этот ADR фиксирует текущие архитектурные решения. Новые решения оформляются отдельными ADR (`0002-...`, `0003-...`) и ссылаются на этот файл, если меняют или отменяют его пункты.

## Решения

### 1. Стек: Vue 3 + TypeScript + Vite

- Vue 3 (Composition API, `<script setup>`), `vue-router`, `idb`, `lucide-vue-next`.
- Сборка через Vite. Алиас `@` указывает на `src/`.
- `strict`, `noUnusedLocals`, `noUnusedParameters` включены. `npm run build` запускает `vue-tsc -b` перед сборкой, поэтому ошибка типов или неиспользуемый код ломает сборку.
- Тестов и линтера нет.

### 2. Offline-first: PWA + IndexedDB

- Источник данных на клиенте — IndexedDB (хранилища `accounts`, `categories`, `operations`, база `allcash`).
- Приложение — PWA (`vite-plugin-pwa`, `registerType: 'autoUpdate'`, precache `js/css/html/svg/png/woff2`, `navigateFallback: /index.html`, `/api` исключён из fallback).
- nginx не кэширует `sw.js`, `workbox-*.js`, `registerSW.js`, `manifest.webmanifest`. Файлы в `/assets/` кэшируются как `immutable`.

### 3. Слои и направление зависимостей

```
features/  ->  core/store  ->  core/data (интерфейс LedgerRepository)
   |               |           core/network (APIClient, DTO, mapping)
   |               v
   +--------->  core/model (чистая логика, без Vue)
design/ — общие UI-компоненты, не зависят от features/
```

- `core/model` — чистая доменная логика без Vue и без I/O: типы реестра, деньги, аналитика, правила валидации, payload'ы синхронизации.
- `core/data` — интерфейс `LedgerRepository` и его реализация `IndexedDBLedgerRepository`. Store зависит от интерфейса, а не от IndexedDB.
- `core/network` — `APIClient`, DTO и `mapping.ts`. DTO не попадают в модель: преобразование DTO ↔ модель делается только в `mapping.ts`.
- `core/store` — `LedgerStore` держит данные в памяти и строит view-модели (`models.ts`).
- `features/*` — экраны и feature-store'ы (`auth`, `sync`, `export`).
- `design/` — переиспользуемые UI-компоненты и `theme.css`.

### 4. Состояние: классы-синглтоны, без Pinia

- `ledgerStore`, `authStore`, `syncStore`, `exportStore` — экземпляры классов, экспортируемые из модуля. Реактивность через `ref`/`shallowRef`/`computed`.
- Компоненты импортируют store напрямую. `provide/inject` и Pinia не используются.
- Производные данные (`days`, `accounts`, `debts`, `currencyTotals`) хранятся в `shallowRef` и пересчитываются store'ом.
- Связывание store'ов делает `MainTabView.vue`: загрузка реестра, автосинхронизация при монтировании и при `visibilitychange`, реакция на `sessionExpired`.

### 5. Навигация

- `vue-router` содержит только четыре вкладки: `operations`, `accounts`, `analytics`, `settings`. Неизвестный путь ведёт на `/operations`.
- Форма операции, sheet'ы и детальные экраны (например, долг) — локальное состояние компонентов поверх `MainTabView`, а не маршруты.

### 6. Синхронизация

- Модель pull/push с серверным порядковым номером: `sync.lastSeq` и `sync.lastSyncedAt` хранятся в `localStorage`.
- Pull идёт страницами (лимит 2000, максимум 100 страниц). Push идёт пачками по 400 записей. Автосинхронизация раз в 60 секунд и при возвращении вкладки в фокус.
- Локальные изменения помечаются как ожидающие отправки (pending). Удаления мягкие: запись помечается удалённой и отправляется на сервер.
- Результат применяют `applyPulled` и `applyPushResult` в репозитории.
- Аутентификация: заголовок `X-Login`. Истёкшая сессия сообщается через `sessionExpired`, `authStore` обрабатывает её. *Заменено ADR-0004: вход по паролю, `Authorization: Bearer <token>`, бессрочный токен.*

### 7. Деньги

- Сумма — `number` с масштабом 2 знака (`scale = 100`).
- Арифметику выполняют только функции из `core/model/decimal.ts` (`add`, `subtract`, `multiply`, `rounded`). Прямое сложение и умножение float запрещено.

### 8. Ошибки

- Сетевые ошибки — размеченные объединения (`APIError`, `SyncError`, `AuthError`), бросаются как `APIFailure`. Текст для пользователя строят функции `*ErrorText`.
- Интерфейс и тексты ошибок — на русском.

## Последствия

- Плюсы: работа без сети, простая модель состояния, изолированная и тестируемая доменная логика, замена хранилища без изменения store.
- Минусы:
  - Автоматических тестов нет, регрессии ловит только `vue-tsc`.
  - Синглтоны затрудняют изоляцию store'ов в тестах.
  - `number` для денег требует дисциплины: обход `decimal.ts` даёт ошибки округления.
  - Глубокие экраны не имеют URL, поэтому ссылки на них и кнопка «назад» браузера не работают.

## Правила для будущих изменений

- Логику предметной области размещать в `core/model`, без импорта Vue.
- Доступ к данным добавлять через `LedgerRepository` и его реализацию.
- Новый серверный формат описывать в `dto.ts` и преобразовывать в `mapping.ts`.
- Изменение любого пункта выше оформлять новым ADR со статусом «Принято» и пометкой «Заменяет ADR-0001, пункт N».
