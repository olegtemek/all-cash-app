# ADR-0002: Локализация интерфейса (русский и английский)

- Статус: Принято
- Дата: 2026-09-30
- Заменяет: ADR-0001, пункт 8 (в части «интерфейс и тексты ошибок — на русском»)
- Связанные ADR: ADR-0001

## Контекст

Интерфейс был только на русском, тексты были вписаны прямо в компоненты, stores и `core/model`. Нужен переключатель языка в настройках с русским и английским.

Ограничения:

- `core/model` не должен импортировать Vue (ADR-0001, п. 3), но именно там строятся многие тексты: ошибки валидации, подписи операций, склонения.
- View-модели (`days`, `accounts`, `debts`) хранятся в `shallowRef` и строятся один раз. Форматтеры `Intl` создаются на уровне модуля с локалью, известной при загрузке.
- Клиент работает без сети, поэтому язык нельзя брать с сервера.

## Варианты

1. **`vue-i18n`** — готовое решение, реактивная смена языка. Новая зависимость, тексты в `core/model` пришлось бы получать через Vue-экземпляр, что нарушает слои. Реактивность не покрывает уже построенные view-модели и форматтеры.
2. **Собственный модуль `core/i18n` без Vue, язык фиксируется при загрузке** — функция `t(key, params)`, два каталога, смена языка перезагружает страницу. Нет зависимостей, работает из любого слоя. Смена языка не мгновенная.
3. **Собственный модуль с реактивной локалью** — смена без перезагрузки. Нужно пересобирать view-модели и все форматтеры, `core/model` зависел бы от Vue-реактивности.

## Решение

Вариант 2.

- Поддерживаются `ru` и `en`. Тип `AppLocale` и текущая локаль `appLocale` лежат в `core/model/locale.ts`.
- Язык выбирается при загрузке: значение `ui.locale` из `localStorage`, иначе первый поддерживаемый язык из `navigator.languages`, иначе `ru`. `interfaceLocale` (`ru-RU` / `en-US`) и `decimalSeparator` выводятся из `appLocale`.
- `core/i18n/ru.ts` — эталонный каталог, ключи плоские вида `раздел.имя`. Тип `MessageKey` выводится из него. `core/i18n/en.ts` типизирован как `Record<MessageKey, string>`: пропущенный перевод ломает `vue-tsc`.
- `core/i18n/index.ts` экспортирует `t(key, params)` (подстановка `{name}`) и `plural(base, count)` (ключи `base.one|few|many|other`, выбор через `Intl.PluralRules`).
- `core/i18n` не импортирует Vue и зависит только от `core/model/locale`. Его можно импортировать из `core/*`, `features/*` и `design/`.
- Переключатель — `select` в `SettingsView`. Смена сохраняет `ui.locale` через `setStoredLocale` и вызывает `window.location.reload()`. Данные лежат в IndexedDB и не теряются.
- `document.documentElement.lang` выставляется в `main.ts`.
- Пользовательские данные не переводятся: названия счетов, категорий, заметки остаются как введены. Исключения на момент создания: системная категория «Коррекция» и заметка правки баланса берут текст текущего языка. Поиск коррекции по имени учитывает оба названия (`correctionNames`).
- Тексты сервера (`error.message`) показываются как пришли.

## Последствия

- Проще: нет новой зависимости, переводы проверяются типами, `core/model` остаётся без Vue.
- Сложнее: смена языка перезагружает страницу. Каталоги надо вести вручную. Русское склонение требует форм `one/few/many` в каждом plural-ключе, английский каталог дублирует их.
- Ранее созданные системные записи (категория «Коррекция», заметки правки баланса) остаются на языке, действовавшем при создании.
- Правила для кода:
  - Не писать пользовательские строки в коде и шаблонах. Добавлять ключ в `ru.ts` и `en.ts`, использовать `t()` / `plural()`.
  - В шаблонах `t` импортируется в `<script setup>`.
  - Не кэшировать результат `t()` между загрузками страницы.
  - Формат чисел и дат брать из `interfaceLocale`.
- Проверка: `npm run typecheck` падает при отсутствии ключа в `en.ts`. `grep -rP "[А-Яа-яЁё]" src` не должен находить строк вне `core/i18n/ru.ts`, комментариев и `correctionNames`.
